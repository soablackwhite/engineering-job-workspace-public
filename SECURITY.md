# Security and privacy reporting

Do not post credentials, private CVs, personal mailbox data or production records in public issues. For a security issue, use GitHub private vulnerability reporting if it is enabled for the repository. If it is unavailable, open a content-free issue requesting a private reporting channel; do not include exploit details or personal data there.

Revoke exposed credentials promptly. Preserve only the minimum private evidence needed for remediation. A successful source scan is not proof that a hosted installation is secure: review authentication, gateway trust, storage access and private backups separately.

For ordinary contributions, use synthetic fixtures and run the privacy checks described in docs/PRIVACY.md.
