# Contributor and agent instructions

Read README.md, ARCHITECTURE.md, docs/PRIVATE_SETUP.md and docs/OPERATIONS.md before changing workflow behavior. This public source repository contains no real candidate profile, CV, mailbox, production endpoint, application history or active execution grant. Never reconstruct those from examples. Default execution is paused; publishing source, passing tests or deploying code never authorizes applications.

Keep all shared qualification, policy, exact identity, duplicate, document, review, lease, revision and submission gates. Missing facts, private configuration or authorization must hold execution. Preserve uncertain attempts and original receipt/document history. Do not turn a legacy synthetic compatibility path into operational permission. One browser owner and one writer per private dataset.

Never commit real candidate documents/answers, contact details, mailbox messages, personal note bodies/indexes, exports, browser captures/cookies, credentials, deployment IDs or local home paths. There is no CV exception. Use reserved example domains and synthetic portable fixtures. Private configuration and artifacts belong under ignored .private/ storage or an explicit external private location.

Tests and CI must not read a real vault, call production services, access Keychain, operate a browser or need credentials. Run scripts/check_public_tree.py plus the relevant tests. Report suspected credential findings by file/line/type only, never values. Do not weaken authentication to make a clone convenient.

Preserve other contributors' changes and work within assigned files. Review staged contents, not only .gitignore. A public release must have clean reachable Git history and no inherited private PR/history references. Do not merge a private operational repository into public source. See docs/PRIVACY.md for release checks.
